Your pools
A pool load-balances across its members (a node + port + weight). The monitor marks members up/down; traffic only goes to healthy ones (fail-open if all down). Click a pool to edit it. Green/red dots update live.
Your policies
A policy is a named ruleset + tuning: a SecLang rules file (usually including CRS), a paranoia level, a body limit, and path-scoped exclusions. Sites reference a policy. Click one to edit it.

Privacy / redaction

High availability
waf-proxy syncs config and computes an active/standby role from peer health. Actual VIP failover belongs to keepalived/VRRP or your load balancer — point its health check at /healthz and read role from /api/ha. Blocklist state is intentionally not shared.

Privacy
Note: forwarding is async and fail-open — a slow or unreachable SIEM never blocks traffic (lines are dropped, not queued forever). WAF logs can carry URIs, client IPs, and payload fragments; prefer TCP+TLS off-box, and the matched payload is omitted unless you opt in above.
Signed self-update
Signed updates aren't enabled in this build (no publisher key baked in, or not on localhost). Rebuild with a publisher public key, or set WAF_PUBLISHER_KEY_FILE, and access the console over ssh -L.
Staged — review before installing
How trust works: packages are verified against the baked-in publisher public key (RSA/SHA-256) before anything is written — a bad signature, checksum, or unsafe path is rejected. The private key stays offline, so a stolen admin session still can't forge an update. Installing replaces the binary and requires a restart; the previous version is kept for one-click rollback. Admin-only, localhost-only.
