Analysis policy
Privacy / redaction
Heads up: analysis is asynchronous — the AI never sits in the request path. It can only add a site-scoped, time-boxed block and fails open on errors. The trusted proxy list is global: forwarded client IPs are accepted only from those network peers, then used consistently by Coraza, logs, ip_hash, AI, and backend headers. Common credential headers and sensitive query parameters are redacted, but request metadata may still be sensitive; keep CRS doing deterministic blocking.
High availability
HA sync uses a dedicated peer-only HTTPS endpoint and a separate replication credential. Configure this node's WAF_HA_PEER_TOKEN locally; enter the peer node's dedicated HA token above. Shared WAF config is replicated, while each node keeps its own HA role/peer/token, users, AI/HSM secret references, and notification webhook secret. Actual VIP failover belongs to keepalived/VRRP or your load balancer — point its health check at /healthz and read role from /api/ha.
Notifications
Events always show in the bell; the webhook is an extra fan-out. Stored webhook URLs are never returned by the config API; leave this field blank to keep the current secret, or use Clear stored webhook to remove it explicitly. Suggestions never auto-apply.
Syslog forwarding to SIEM
Streams to forward
Privacy
Note: forwarding is async and fail-open — a slow or unreachable SIEM never blocks traffic (lines are dropped, not queued forever). WAF logs can carry URIs, client IPs, and payload fragments; prefer TCP+TLS off-box, and the matched payload is omitted unless you opt in above.
Signed self-update
Signed updates aren't enabled in this build (no publisher key baked in, or not on localhost). Rebuild with a publisher public key, or set WAF_PUBLISHER_KEY_FILE, and access the console over ssh -L.
Staged — review before installing
How trust works: packages are verified against the baked-in publisher public key (RSA/SHA-256) before anything is written — a bad signature, checksum, or unsafe path is rejected. The private key stays offline, so a stolen admin session still can't forge an update. Hardened DEB/RPM/systemd deployments intentionally use the external package manager for privileged installation; direct install is only available with an explicit standalone WAF_UPDATE_INSTALL_DIR. Admin-only, localhost-only.
